# Upstream v0.2.16 Follow-Up Verification

Date: 2026-08-10

## Baseline And Scope

- Upstream release: `v0.2.16`.
- Local fixed point: `dev` at `0abff8c87afd901a9f626f23a516204f6e6469cb`.
- Backend remains FastAPI/Python only. No Java, Spring, Maven, Redisson, or
  Flyway runtime was reintroduced.
- CLI remains `cli-v0.1.9`; the release did not require a CLI bump.

## Alignment Decisions

- Adapted upstream sub-path routing to the existing runtime-config design. One
  web image supports root, Istio-stripped `/skillhub`, and raw `/skillhub`
  requests without build-time path baking.
- Added reserved first-segment validation, same-origin API-base validation,
  root-safe Nginx generation, exact prefix redirect, and raw-prefix
  redispatch.
- Ported label-chip search navigation and the narrow React 19 overlay portal
  isolation fix. Existing CJK redirect handling was retained and regression
  tested.
- Ported version-delete locking and FK safety to the Python lifecycle. Rejected
  review evidence is archived before deletion, existing notification IDs keep
  resolving through the archive reader, and legacy rejected rows without a
  review task remain deletable.
- Adapted request/message correlation to the production `SkillHubRedisClient`,
  with bounded request IDs and consumer context cleanup.
- Ported label search rebuild observability as one bounded retry, final-failure
  logging, and a Prometheus counter.
- Added SHA-256 verification for bundled starter manifests. No new upstream
  starter catalog item is enabled by default because that would add startup
  supply-chain and availability coupling.
- Ported smoke-admin credential isolation. Spring MVC error mapping and ambient
  Java type changes are Python no-ops.
- Full OpenTelemetry SDK/exporter integration remains deferred. Request/Redis
  correlation is present and startup does not depend on an external collector.
- Documentation/community-only upstream commits required no runtime port.

## Review Findings Closed

- Production container logs exposed an incorrect redis-py keyword passed to
  `SkillHubRedisClient.xreadgroup`. The consumer now uses the wrapper's
  `block_ms` and keyword-only reclaim contract; a real Redis test now creates
  the production wrapper rather than bypassing it.
- Code review found that deleting a rejected version removed its terminal
  `review_task`. The transaction now snapshots the rejected attempt into
  `review_attempt_archive` before deleting the task and version.
- A real PostgreSQL barrier test reproduced delete winning against lifecycle
  review submission as an FK `IntegrityError`. Submission now performs a
  conditional `UPDATE ... RETURNING`; the losing operation returns
  `409 review.concurrent_update`. The inverse submit-wins ordering is also
  forced and rejects deletion through the lifecycle status contract without a
  deadlock or 500.
- Label rebuild retry/metric coverage, explicit Nginx upload/SSE routing, and
  overlay navigation teardown coverage were added after review.
- A second Standards and Spec review found no remaining actionable P0-P3
  finding or scope creep.
