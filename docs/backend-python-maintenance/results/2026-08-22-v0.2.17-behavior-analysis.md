## Executive Conclusion

`v0.2.17` is not a database, scanner algorithm, CLI, Compose, or Kubernetes
topology upgrade. Its material behavior is concentrated in four areas:

1. immutable version-level `x-astron-compliance` declarations and UI;
2. a platform-administrator namespace console and super-admin read/governance;
3. correctness fixes for API-token reachability, scan-task transaction timing,
   and private confirm-publish downstream events;
4. one applicable Aliyun stop-instruction fix; the Bash launcher change applies
   to upstream's retired Java `server/` path and is currently a Python-fork
   no-op.

The current Python fork does not yet implement the compliance or admin-console
contracts. It partially covers token and namespace behavior, but has confirmed
behavioral gaps in bearer star/rating, scan-task delivery timing, and
confirm-publish downstream handling. The existing follow-up plan
[`2026-08-21-follow-upstream-v0.2.17.md`](../plans/2026-08-21-follow-upstream-v0.2.17.md)
has the right scope; the local findings below refine how it should be executed.

## Upstream Compliance Contract To Preserve

The implementation should match the official parser, not only the UI:

- maximum 50 mappings per version and 10 evidence items per mapping;
- required `standard`, `version`, and `controlId`;
- `standard` normalized to lowercase and limited to 64 characters;
- `version` limited to 64 characters, `controlId` to 128, and optional `title`
  to 200;
- duplicate key is normalized `standard + version + controlId`;
- evidence types are exactly `packaged-file` and `external-url`;
- packaged paths are normalized, cannot escape the package, must exist, and
  include a SHA-256 in the snapshot;
- external URLs are HTTP(S), include a host, and are limited to 2048
  characters;
- digest is `sha256:` plus the SHA-256 of deterministic JSON containing
  `schemaVersion` and normalized `items`;
- absent metadata remains valid and projects as no snapshot.

These limits and algorithms come directly from the tagged
[`ComplianceMetadataService`](https://github.com/iflytek/skillhub/blob/15ce199e1a951fed05139e4c984150ddfc45def3/server/skillhub-domain/src/main/java/com/iflytek/skillhub/domain/skill/metadata/ComplianceMetadataService.java).

## Recommended Update Sequence

1. **Freeze contracts with failing tests.** Add exact compliance fixtures,
   token route-matrix cases, namespace super-admin cases, scan commit/rollback
   barriers, and confirm-publish downstream assertions before production code.
2. **Fix transaction/auth/event correctness first.** Move Redis `XADD` after
   PostgreSQL commit, pass bearer identity through star/rating, and add the
   local post-commit publication seam for confirm-publish search and subscriber
   notifications.
3. **Add compliance backend without a migration.** Validate and snapshot during
   publish/dry-run; preserve historical JSON compatibility; project into
   version/detail/search/review APIs and rebuild/incremental search paths.
4. **Add admin namespace APIs and UI.** Reuse existing Python member and
   lifecycle modules behind an explicit `SUPER_ADMIN`, session-only facade;
   keep analytics independent.
5. **Finish frontend, scripts, and docs.** Regenerate API types from the Python
   contract, add all three local languages, fix the Aliyun script, record the
   Java-only Bash launcher no-op, and update protocol/operator/user
   documentation.
6. **Verify the full deployed path.** Use real PostgreSQL, Redis, object storage,
   backend, scanner/consumer, production web image, and both `/` and `/skillhub`.

## Verification Required For Acceptance

- PostgreSQL transaction tests prove scan task: one after commit, zero on
  rollback, and no worker observation of uncommitted rows.
- Redis failure after commit has a tested retry/compensation outcome rather
  than silently leaving an unrecoverable `SCANNING` version.
- Confirm-publish refreshes search and produces owner/subscriber notification
  state exactly once; rollback and replay produce no duplicate effects.
- Session and bearer route matrix covers public auth/labels, downloads,
  star/unstar/rating, session-only admin, and unsupported routes.
- Compliance tests cover every limit/error above, deterministic digest,
  historical no-field rows, immutable prior versions, search rebuild, review
  diff, and OSS/native publish paths.
- Admin namespace tests use real PostgreSQL for super-admin non-member access,
  GLOBAL immutability, last-owner/transfer invariants, lifecycle transitions,
  audit, concurrent updates, and rollback.
- Frontend typecheck, lint, full tests, production build, three-locale coverage,
  and browser smoke pass for root and `/skillhub` without console errors.
- CLI regression tests, Compose rendering, Kustomize base/external rendering,
  script contract tests, backend/frontend image builds, and `git diff --check`
  pass.

## Explicit Non-Goals

- Do not reintroduce Java, Maven, Spring Boot, Spring events, Flyway, or a hybrid
  backend.
- Do not add a schema migration or compliance table without separate measured
  evidence that existing JSONB cannot satisfy the contract.
- Do not treat publisher compliance declarations as verified execution traces,
  certification, enforcement, or platform endorsement.
- Do not change scanner analyzers/protocol, bump or publish the CLI, add Helm,
  or change K8s/Compose workload topology.
- Do not broaden bearer access to admin, subscription, or label-mutation routes
  not opened by upstream `v0.2.17`.
- Do not replace the existing `/admin/namespace-analytics` investigation and
  metrics page with the new governance console.
- Do not copy the upstream weekly-report site or unrelated community content.
