# Upstream v0.2.17 Batch 2A Compliance Ingestion Checkpoint

Date: 2026-08-23
Branch: `codex/upstream-v0.2.17-risk-first`
Baseline: `origin/dev` at `8cf2923bcb49b191f228f7f9106090fc4b892e6e`

This checkpoint covers compliance metadata ingestion and immutable version
persistence only. It adds no API projection, search projection, review diff,
frontend behavior, schema migration, commit, or push.

## Accepted Contract

- `x-astron-compliance` remains optional for existing packages.
- A version accepts at most 50 mappings and 10 evidence items per mapping.
- `standard`, `version`, and `controlId` are required strings, with limits of
  64, 64, and 128 characters. Optional `title` is limited to 200 characters.
- Standards are normalized to lowercase and must match
  `[a-z0-9][a-z0-9._-]*`; control IDs must match
  `[A-Za-z0-9][A-Za-z0-9._:-]*`.
- Duplicate normalized `(standard, version, controlId)` tuples are rejected.
- Evidence types are limited to `packaged-file` and `external-url`.
  Packaged paths are limited to 512 characters, must be normalized and remain
  inside the package, must exist, and receive a content SHA-256. External URLs
  are limited to 2048 characters and require HTTP(S) plus a host.
- Snapshot schema `1.0` and mapping/evidence order are preserved. The digest is
  `sha256:` plus the SHA-256 of deterministic JSON containing `schemaVersion`
  and normalized `items`.

## Storage Boundary

New version rows retain top-level `name`, `description`, and `version` for
historical bare-row readers. They also persist the complete package
frontmatter under `frontmatter` and the normalized declaration under
`complianceSnapshot` in the existing `skill_version.parsed_metadata_json`
JSONB column. Unknown frontmatter remains preserved. Versions without the
reserved field receive a deterministic empty snapshot; historical rows are
not rewritten.

Both dry-run and real publish use the package validator. Version creation also
rebuilds the snapshot inside the database transaction, so a caller that
bypasses dry-run still cannot persist malformed compliance metadata or write
package objects.

### Tagged Java parity review

A subsequent specification review found two Python/Java semantic gaps. A
second RED run demonstrated both before the correction:

```text
10 failed, 114 passed in 0.74s
```

The failures proved that Python `strip()` removed non-breaking spaces that
Java `String.trim()` preserves, Python `len()` counted Unicode code points
instead of UTF-16 code units, and `urllib.parse.urlsplit()` accepted raw URI
characters and malformed percent escapes rejected by Java `URI.create()`.

The isolated compliance module now uses focused Java-parity helpers:

- `isBlank()`-compatible Unicode whitespace classification;
- `trim()`-compatible removal of only characters through U+0020;
- UTF-16 code-unit length checks, including rejection of a 33-emoji value
  against the 64-unit limit;
- strict raw URI character and percent-escape validation followed by HTTP(S)
  scheme and Java-compatible server-host validation.

NBSP-padded versions and titles remain byte-for-byte present in the normalized
snapshot and deterministic digest, while NBSP-padded standards/evidence types
remain invalid under their allowed-value patterns.

The corrected focused run, including native publish, storage, orchestration,
source-import validation, and real PostgreSQL, passed:

```text

```

### Component-specific URI and package-path parity review

A second specification review found that the global URI character whitelist
still differed from Java's component and `getHost()` behavior, and that the
general package path normalizer still used Python Unicode `strip()`. Tests were
added before the correction. The RED run reported:

```text
22 failed, 127 passed in 0.87s
```

The failures covered brackets in paths, multiple `@` delimiters, numeric TLDs
in multi-label hosts, the then-assumed 65535 port boundary, Java-valid empty
ports, Java-valid U+200D path characters, and NBSP/em-space package paths used
as packaged evidence.

URI validation now applies distinct rules to scheme, authority and user-info,
domain or IP host, port, path, query, and fragment. It retains strict percent
escape checks; rejects raw spaces, controls, backslashes, illegal ASCII path
characters, ambiguous authorities, numeric TLDs in multi-label hosts, and Java
integer port overflow; and accepts empty ports plus Java URI `other` characters
such as U+200D outside the host. This remains a dependency-free Python
implementation.

Java-compatible `isBlank()`, `trim()`, and UTF-16 length behavior now live in a
focused shared helper. Both package entry normalization and compliance evidence
lookup use the same `trim()` semantics, so NBSP and em-space remain part of the
path, package lookup finds the exact entry, and the evidence hash binds its
content.

### Final URI host and deterministic digest boundary review

A final `URI.getHost()` review corrected the remaining host and port details.
The URI-focused RED run reported:

```text
18 failed, 157 passed in 0.86s
```

Explicit non-negative ports are now accepted through Java
`Integer.MAX_VALUE` (`2147483647`), including 65536, while 2147483648 is
rejected. Single-label `123` and `1abc` hosts are accepted; the alphabetic
rightmost-label constraint applies only to multi-label hostnames. Dotted IPv4
validation accepts Java-compatible leading zeroes such as `010.000.000.001`.
IPv6 scope IDs accept only ASCII letters, digits, underscore, and dot, so
`%eth_0` and `%eth.0` remain valid while `%eth-0` is rejected.

An independent publish-boundary review also found that a YAML title containing
a lone UTF-16 surrogate could pass dry-run and then raise `UnicodeEncodeError`
during deterministic snapshot serialization. Tests reproduced that failure:

```text
3 failed, 175 passed in 0.79s
```

All compliance string fields now reject surrogate code units with a normal
`must contain valid Unicode` validation error. Package validation and dry-run
return that error, and publish preparation raises `ComplianceMetadataError`
before any `skill_version` insert rather than leaking an encoding exception.

### IPv4-embedded IPv6 exact parity review

The last URI review found that Python `ipaddress` rejected Java-valid
IPv4-embedded IPv6 literals when dotted octets contained leading zeroes. Tests
covered compressed and uncompressed forms through package validation, dry-run,
and publish snapshot creation. The RED run reported:

```text
6 failed, 178 passed in 0.84s
```

IPv6 validation now detects a dotted tail, validates it with the same
Java-compatible IPv4 rules used for ordinary hosts, and canonicalizes only a
temporary copy before Python performs IPv6 structural validation. Therefore
both `[::ffff:010.000.000.001]` and
`[0:0:0:0:0:ffff:010.000.000.001]` validate, while the submitted URL remains
unchanged in the immutable compliance snapshot. Existing host, port, scope-ID,
path, query, and fragment behavior is preserved.
