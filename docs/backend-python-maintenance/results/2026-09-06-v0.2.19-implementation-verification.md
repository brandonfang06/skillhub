### CLI

```powershell
cd cli
bun test
bun run lint
bun run build
```

```text
450 passed, 6 skipped, 0 failed；456 tests in 76.21s
ESLint：passed
Node bundle：passed
連續 300 次 Windows target-lock collision：passed
```

6 個 skip 是既有的 Windows symlink capability 案例。針對已追蹤 CLI 原始碼與
測試的 scoped TypeScript 檢查已通過。一般的 `bun run typecheck` 仍會納入與本次
工作無關、原先即未追蹤的
`cli/test/prototypes/copyable-multiline-install-prototype.ts`；該 prototype 在第 20
行有既存的 `string | undefined` 錯誤。為避免把使用者工作吸收到本次 release
follow-up，沒有修改該檔案。

Windows 併發診斷成功重現 stale-lock cleanup 的 ABA race：兩個 process 可能同時
看到舊 lock，其中一個會移除另一個 process 剛取得的新 lock。現在以短期 recovery
coordinator 序列化 stale-lock 的取得與復原；一般 target lock 仍保留有界的
Windows `ENOENT`／`EPERM`／`EACCES` retry。

## 安全與治理檢查

- 被隱藏的評論文字、作者 attempt 歷史與詳細 scanner failure 均依角色限制；
  公開 response 只提供安全 projection。
- 掃描重試在 server-side 檢查權限，bearer caller 需要 `skill:publish` scope；
  active attempt 具冪等性，而且不能利用重試繞過 review。
- Version、audit 與 outbox 狀態變更保持交易一致；晚到的 scanner 結果不能覆蓋
  較新的 attempt。
- CLI force 不會繞過來源 ownership、unmanaged directory 防護、fingerprint 或
  fork 原有的 multi-target rollback 契約。
- Browser 與 CLI registry URL 維持分離，從 request 推導的安裝指引會拒絕惡意
  Host input。
- Notification cache 依 user identity 隔離；Playground streaming 未被修改。
- `git diff --check` 已通過，沒有殘留臨時 debug instrumentation，變更路徑中也
  沒有加入 Java、Maven 或 Spring runtime 檔案。
