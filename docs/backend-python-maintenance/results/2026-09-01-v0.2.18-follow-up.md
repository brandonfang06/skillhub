## Outcome

The applicable v0.2.18 contracts are implemented and verified in the
Python-only fork. No Java, Maven, Spring Boot, Flyway runtime, or hybrid
backend was introduced.

Personal namespace provisioning remains explicitly deferred. This work does
not create personal namespaces, default memberships, account backfills,
naming/collision policy, or related operator settings. Namespace manifests and
CLI sync operate only on namespaces that already exist and are accessible to
the authenticated principal.

No commit, push, PR, deployment, package publication, tag, or release was
performed.

## Implemented scope

### Durable scan delivery

- Added Python-owned V44/V45 migrations for a PostgreSQL scan-task outbox and
  durable task metadata.
- Made publication state, security audit, and scan intent one transaction.
- Added bounded retry, lease reclaim, terminal failure, sent-row cleanup, and
  task-id consumer idempotency.
- Removed request-path Redis publication and cleans obsolete outbox records on
  replacement, version deletion, and skill deletion.

### Backend and API contracts

- Added bearer-authorized namespace manifests for existing namespaces.
- Added disabled-by-default configurable rate limits with complete Compose and
  K8s wiring.
- Added bounded label/owner projections, current-access subscription checks,
  legacy slug ordering coverage, OAuth identity/return-path hardening, strict
  publish conflict handling, persisted publish status, and ZIP path defenses.
- Regenerated the FastAPI-derived frontend OpenAPI schema.

### CLI

- Added `sync pull`, `sync status`, `sync diff`, and `sync push` with paginated
  manifests, deterministic fingerprints, local-change protection, verified
  archive replacement, safe prune behavior, strict publish validation, and
  per-item failure reporting.
- Preserved the fork's stronger atomic multi-target install and inventory
  rollback behavior.
- Kept the package at `0.1.9`; no local `0.1.10` publication was authorized.

### Web

- Added deterministic browser folder-to-ZIP publishing with backend-equivalent
  entry, path, and size boundaries.
- Ported applicable auth redirect, notification, relative-time, owner display,
  select overflow, and browser compatibility fixes.
- Added complete Russian locale support, self-hosted fonts, and the OIDC asset
  without weakening CSP.
- Preserved both root and `/skillhub` deployment behavior.

### Deployment and documentation

- Runs the Python server image as UID 100/GID 101 with writable retained
  storage and a multi-stage build that can compile required source
  distributions.
- Added Server/Web RISC-V release workflows and contract checks. Scanner and
  full Compose remain explicitly outside the RISC-V claim.
- Hardened Nginx version disclosure and build-platform handling.
- Added Python-only RISC-V, content safety, privacy/data governance, Python
  client examples, operator settings, migration/outbox, CLI sync, and folder
  publish documentation.

## Security and governance review

- CIA review and changed trust boundaries are recorded in the execution scope.
  Confidentiality protects OAuth/bearer credentials and package content;
  integrity binds publication, outbox, scanner, audit, and CLI fingerprints;
  availability is covered by rate limits, bounded retries, leases, terminal
  evidence, and restart recovery.
- PostgreSQL remains the source of truth for scan delivery; Redis is an
  asynchronous boundary and cannot make an already committed publication lose
  its delivery intent.
- Terminal outbox exhaustion now records failed local scan-execution evidence
  together with `SCAN_FAILED`, so security-audit projections cannot remain
  falsely pending.
- Namespace manifests, sync, publish, and review operations retain bearer
  scope and namespace-access enforcement. Tokens are not written to workspace
  metadata.
- Namespace manifests select an independently published, downloadable version
  when the workflow pointer references a pending or private owner preview.
- GitHub verified-email lookup accepts only credential-free HTTPS endpoints,
  does not follow redirects, and bounds response type and size before parsing.
- All 37 rate-limited route aliases cover authenticated and anonymous
  principal behavior in the HTTP contract suite.
- Archive extraction and browser ZIP creation enforce normalized paths,
  traversal rejection, entry limits, per-file limits, and aggregate limits.
- Subscription fan-out rechecks current visibility and membership.
- New privacy/content-safety docs describe the implemented processing and do
  not claim external sharing or retention behavior that the Python runtime
  does not provide.

## Deviations and remaining risks

- Docker Desktop's containerd image store pulled the official Python RISC-V
  manifest but failed to execute it even after binfmt registration (`exec
  format error`). With the classic image store, the same official image ran and
  reported `riscv64`; the host and QEMU path therefore work, and the failure is
  isolated to the containerd snapshotter path. The dedicated CI workflow and
  static release contract remain the authoritative checks for the actual
  SkillHub RISC-V images; AMD64 images were built and exercised locally.
- `scanner/` has no upstream v0.2.18 source delta or local package test suite.
  Scanner protocol remains unchanged; acceptance is through real Redis
  delivery/idempotency tests and explicit exclusion from the RISC-V matrix.
- Port 3000 was occupied by unrelated Docker/WSL forwarding, so root Playwright
  used its supported external-base-URL mode on port 3100. No application or
  test configuration was weakened for this machine-specific collision.
- Ruff is not installed in the frozen backend environment and the repository
  is not globally Ruff-clean: an optional one-shot full-tree scan reported 422
  existing baseline findings. This follow-up fixed only the six findings in
  newly added files and left unrelated lint debt untouched.
- Personal namespace policy still requires a separate product/governance
  decision before any implementation.
