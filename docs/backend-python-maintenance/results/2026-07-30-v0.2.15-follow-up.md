# Upstream v0.2.15 Follow-Up Result

**Date:** 2026-07-31

## Scope And Decisions

This follow-up ports the applicable behavior from upstream SkillHub `v0.2.15`
without reintroducing Java or changing the published CLI version.

- Rejected versions may be corrected and resubmitted with the same semantic
  version by the same owner. The completed rejection is archived before the
  active candidate is replaced.
- Published, yanked, pending, other-owner, inactive-skill, and
  inactive-namespace cases remain immutable or blocked.
- A corrected rejected version always creates a new pending review, including
  when the publisher is a platform `SUPER_ADMIN`.
- Archived review links retain feedback, metadata, file hashes, scanner
  summary, and replacement linkage, but no package, file preview, security
  audit, or ZIP download.
- API-token authorization failures use a structured, localizable public code
  and preserve the request ID. Unknown or unstructured `403` bodies are not
  exposed by the web UI or CLI.
- OAuth providers with blank or documented placeholder client IDs are hidden.
- Label attach, detach, definition update, and delete refresh affected search
  documents only after the label transaction commits. Refresh failures are
  logged and cannot roll back the mutation.
- Device authorization already used JSON Redis values; production code was
  retained and serialization plus single-use concurrency behavior was added
  to regression coverage.
- CLI source now accepts `slug`, `namespace/slug`, `@namespace/slug`, and
  `namespace--slug`, rejects conflicting `--namespace`, and makes explicit
  namespace removal precise. A bare slug retains cross-namespace local removal
  compatibility.
- Existing stale lazy-chunk recovery was retained rather than duplicated.
- Forwarded protocol trust is opt-in through
  `SKILLHUB_TRUST_FORWARDED_PROTO=false` across Docker Compose, Kustomize, and
  plain Kubernetes manifests.

## Review Findings And Controls

The final review used runtime scenarios in addition to the test suite.

- A promoted `SUPER_ADMIN` could initially have auto-published a corrected
  rejected version. Publish resolution now disables auto-publish for this
  path, while orchestration keeps a second transaction-level guard.
- The former frontend "increase the version" branch survived the first backend
  change and would have shown stale guidance if an old server returned that
  code. It was removed and is covered by a regression test.
- Kubernetes initially did not inject the forwarded-protocol setting into the
  frontend container. Base, external overlay, and plain manifests now share
  the explicit false-by-default contract.
- The release Compose healthcheck initially called `wget`, which is absent from
  the Python slim runtime and left a working backend marked unhealthy. It now
  uses Python `urllib.request`; the recreated backend and web containers both
  report healthy.
- Archived artifact routes authorize the caller before returning `410`, so
  archive existence is not disclosed to unauthorized users.
- Replacement locks the skill and version, rechecks owner, coordinates,
  lifecycle state, namespace state, and pending-review status, then archives,
  replaces, audits, and creates the new review in one transaction. Old object
  deletion remains post-commit with compensation on failure.

One operational side effect remains intentional: label search refresh runs
after commit and is awaited by the request. Large label-definition changes can
increase admin-route latency, but each skill refresh is isolated, failures are
logged, and label correctness does not depend on index refresh success.

## Deliberate No-Ops

- Redis Cluster was not added because it is an optional deployment choice and
  no organization requirement was approved. Existing standalone, URL, and
  Sentinel behavior remains unchanged.
- Helm was not added because it would introduce a third maintained deployment
  surface and requires separate approval.
- PostgreSQL `lost+found` handling is not applicable to the current
  external-service Kubernetes topology.
- Scanner code, versions, provider secrets, ports, and deployment topology are
  unchanged because upstream `v0.2.15` has no scanner delta.
- CLI package and generated metadata remain content-identical at `0.1.9`;
  namespace support is a source-only divergence pending an official CLI
  release.
- Upstream FAQ text allowing anonymous public installs was not adopted because
  this fork intentionally requires authentication for downloads.

No commit, push, deployment, package publication, or chart publication was
performed.
