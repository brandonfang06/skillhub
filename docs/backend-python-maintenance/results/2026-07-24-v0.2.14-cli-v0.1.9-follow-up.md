# Upstream v0.2.14 and CLI v0.1.9 Follow-Up Result

## Outcome

The Python-only SkillHub fork now covers the applicable upstream `v0.2.14`
and `cli-v0.1.9` changes:

- interactive user-scope CLI installs always offer the generic
  `~/.agents/skills` target;
- equivalent targets are deduplicated through existing and nearest-existing
  ancestor canonicalization, including Windows case-insensitive identities;
- every install target is preflighted before registry requests or filesystem
  writes;
- explicitly scoped repeated `--agent` values install to every requested target
  without an ambiguity error;
- multi-target filesystem and inventory commits roll back as one operation when
  a later target fails;
- force replacement removes stale inventory entries through canonical path
  aliases;
- unsafe empty, traversal, separator-bearing, and NUL-containing skill slugs
  are rejected before registry requests or filesystem writes;
- the scanner image pins `litellm==1.90.2` while preserving
  `cisco-ai-skill-scanner==1.0.2` and the local LLM base-URL backport;
- CLI package metadata reports `0.1.9`;
- bilingual Hermes, CLI, and selected Python-compatible FAQ documentation is
  present.

No FastAPI route, OpenAPI contract, database schema, migration, frontend
runtime, or Kubernetes deployment contract changed.

## Implemented Changes

### CLI target resolution and installation

- Added canonical path helpers for existing paths and paths whose final
  segments do not yet exist.
- Interactive user scope now offers the generic user target alongside detected
  agent-specific targets.
- Canonical aliases are collapsed before prompting. This includes aliases
  below linked parents whose skill roots have not yet been created.
- Install preflight checks every destination before creating the registry
  client.
- Installation stages every target before commit. A later runtime conflict or
  inventory failure rolls back earlier new directories, restores force
  replacement backups, and restores the pre-install inventory.
- Duplicate canonical destinations fail with a usage error before network or
  writes.
- Windows identities are compared case-insensitively.
- Explicit repeated `--agent` values are authoritative even when `--scope` is
  also present; they no longer fall through to auto-detection ambiguity logic.
- Force replacement removes prior inventory records by canonical install path,
  so junction, symlink, and Windows case aliases do not leave duplicate rows.
- Install slugs must be one safe path segment. Empty values, `.`, `..`, both
  path separators, and NUL are rejected before a registry request or write.
- Final rename race checks remain in place.

Adversarial review found five user-visible correctness defects. Canonicalizing
only a complete existing root missed aliases beneath linked parents when the
final root did not exist. A malformed slug could escape the selected skills
root, while an empty slug with `--force` reached a rename attempt against the
root itself. A race at a later target left an earlier target installed.
Inventory rows written through a canonical alias survived force replacement.
Finally, explicit repeated agents combined with `--scope` were rejected as
ambiguous. The implementation now protects each case with regression coverage.

### Scanner

- `scanner/Dockerfile` installs `cisco-ai-skill-scanner==1.0.2` and
  `litellm==1.90.2` in the same layer.
- The existing `apply_1_0_2_llm_base_url_backport.py` execution, non-root user,
  health check, and build-dependency cleanup are unchanged.
- The scanner source contract is protected by
  `server-python/tests/test_scanner_image_contract.py`.
- The Docker LLM base-URL test now converts its bind-mount source to a Windows
  absolute path and disables MSYS argument conversion only for `docker run`.
  Linux execution remains unchanged.

### Documentation and metadata

- Added bilingual Hermes Agent integration guides, contract-reviewed against SkillHub
  `v0.2.14`, CLI `0.1.9`, and Hermes `0.18.2`.
- Linked the Hermes guides from both root READMEs.
- Updated all three CLI guides for generic user-target selection and custom
  `--dir` usage.
- Added selected FAQ guidance for scanner provenance/pins, CLI publish
  validation, package layout, PostgreSQL support, and Python image/CLI version
  inspection.
- Rejected upstream FAQ text tied to Java, Maven, Spring Boot, Flyway,
  Actuator, the removed `server/` tree, or an unpinned scanner.
- Changed `cli/package.json` to `0.1.9` and regenerated
  `cli/src/generated/pkg-info.ts` with the repository generator.

## Side Effects

- Interactive user installs gain one additional selectable generic target.
  Explicit `--agent`, explicit `--dir`, JSON, non-interactive, and project-scope
  behavior is unchanged.
- Two textual targets that resolve to the same destination now collapse during
  resolution or fail during preflight instead of causing a partial install.
- A pre-existing conflict in any selected target now prevents the download and
  all writes. This is intentionally stricter and removes partial success.
- A conflict or inventory failure discovered after staging begins now restores
  every target in the current command instead of returning partial success.
- Explicit repeated `--agent` values now remain authoritative with `--scope`;
  this converts a prior usage error into the requested multi-target install.
- Canonical alias cleanup can remove an older duplicate inventory row that
  points to the same physical install directory.
- Malformed slugs that could be interpreted as filesystem paths now fail
  locally with a usage error instead of reaching the registry or install loop.
- The scanner build is reproducible for LiteLLM but will not receive newer
  LiteLLM fixes until the pin is deliberately reviewed.
- The scanner Docker test creates temporary local images. It does not publish
  images or start persistent services.
