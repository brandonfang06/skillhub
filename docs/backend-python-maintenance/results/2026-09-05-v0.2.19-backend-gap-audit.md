## 4. Retry / late result / unavailable age：部分涵蓋

上游 SecurityScanRetryAppService 新增：
`POST /api/v1/skills/{skillId}/versions/{versionId}/security-audit/retry`。
目前沒有 web alias，不自行擴充。角色為 skill owner、namespace OWNER/ADMIN、
SKILL_ADMIN/SUPER_ADMIN；API token 需 skill:publish。

- 鎖定 version 並確認屬於該 skill；只有 SCAN_FAILED 或 active SCANNING 路徑。
- SCANNING 且已有 active unscanned audit：冪等返回，不再排 task。
- disabled scanner、缺少原 bundle 拒絕；重試使用既存版本 bundle。
- 建立新 attempt，RETRY_SECURITY_SCAN audit 與狀態改變同一 transaction。
- 回應含 skillId、versionId、action=RETRY_SECURITY_SCAN、status=SCANNING。

本地 `server-python/app/api/security_audit.py:39` 只有讀取路徑；
`publish/scan_worker.py:182,210` 已有 lease/processed task guard，
`publish/scan_outbox.py` 已有 durable dispatch。
但 `publish/scanner_result.py:89` 的 result application 接收 version_id
而非 task identity，並在約 103 行選 latest nondeleted audit；需測並防止
舊 attempt 的晚到結果寫進新 attempt。新 retry 沿用 outbox，不另建直送 Redis。

上游新增最大 unavailable age，預設 PT1H。本地已有 terminal failure，
但仍需明確 unavailable-age convergence，不能把已有 outbox 說成缺漏。
failure reason 是受限 audit 資訊，公開 API/UI 不可洩漏底層診斷或 credentials。

## 5. Scanner 容量與硬逾時：缺漏

上游 `scanner/skillhub_scanner_app.py`：只攔 /scan、/scan-upload，預設並行
1、busy 503 + Retry-After 30、disconnect 後 shield 工作仍占 slot；hard
timeout 930 秒後 process exit 124，由容器重啟。health 不占掃描 slot。
啟動清理 skill_scanner_* 暫存，fork 必須限制在已驗證的 scanner-owned root。

本地 `scanner/Dockerfile` 直接啟動 skill-scanner-api，已有 Cisco 1.0.2、
LiteLLM 1.90.2 和兩個 LLM backport。新增 wrapper 不移除這些相容性修補。
上游 timeout budget 為 read 900s / hard 930s / reclaim 960s；本地
SKILLHUB_SCAN_CONSUMER_RECLAIM_MIN_IDLE_MS 是毫秒，不能填 ISO duration。
需真 container 測 overload、取消、逾時退出和 restart recovery，不只 mock。
