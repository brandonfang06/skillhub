## Implemented

- Added Python backend `canChangePassword` behavior for auth-me/session/local/direct/OAuth/bearer paths.
  - Local password login/register/direct login return `true`.
  - OAuth, bearer, mock, and credentialless users default to `false` unless a local credential is proven.
- Hardened Python admin user role mutation so non-`SUPER_ADMIN` actors cannot modify users who currently hold `SUPER_ADMIN`.
- Ported promotion review list behavior:
  - richer source skill metadata
  - stable pending order
  - approved/rejected reviewed-time sorting
  - stricter invalid status/sort handling
- Updated frontend security settings and user menu to use backend-authoritative `canChangePassword`.
- Updated promotion dashboard, promotion hook, i18n, and tests for the richer review workflow.
- Ported nested markdown preview links from the skill detail preview dialog.
- Added the `undici@<7.28.0` pnpm override and refreshed the lockfile.
- Pinned the scanner image to `cisco-ai-skill-scanner==1.0.2` and added the upstream local LLM base URL backport.
- Confirmed K8s base/plain scanner deployments expose:
  - `SKILL_SCANNER_LLM_API_KEY`
  - `SKILL_SCANNER_LLM_BASE_URL`
  - `SKILL_SCANNER_LLM_MODEL`
- Updated scanner/security/auth docs for the new env and auth capability behavior.

## Review Notes

- The promotion SQL order clause is generated only from validated constants (`reviewedAt`, `ASC`, `DESC`, or pending default), so the formatted SQL does not introduce a user-controlled SQL injection path.
- `web/src/api/generated/schema.d.ts` was not manually edited. The current Python FastAPI app still emits generic object response schemas for auth/promotion routes, so regenerating from Python would not produce the Java-style `AuthMeResponse`/`PromotionResponseDto` components yet. This is an existing Python OpenAPI typing gap and should be handled in a separate typed-response-model milestone.
- The CLI version was already `0.1.8`; no CLI metadata change was needed for this app release follow-up.
