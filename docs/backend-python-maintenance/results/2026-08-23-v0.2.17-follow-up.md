## Runtime requirement discovered during acceptance

Running a healthy scanner container is not sufficient to complete queued scans.
For deployments that expect backend-managed scan consumption, set:

```text
SKILLHUB_SCAN_CONSUMER_ENABLED=true
```

With the release Compose default of `false`, publish requests correctly enqueue
Redis scan tasks, but versions remain `SCANNING` until an external consumer or a
backend instance with the consumer enabled processes them. This is existing
deployment behavior, not a new v0.2.17 dependency.
