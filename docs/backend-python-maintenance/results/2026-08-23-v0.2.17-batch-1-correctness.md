## Accepted Behavior

- Scan tasks are published only after the PostgreSQL publish transaction
  commits. Rollback emits zero tasks.
- Scanner-enabled writes reject a missing task publisher before opening a
  transaction.
- A failed or uncertain Redis `XADD` is compensated by moving an eligible
  version from `SCANNING` to `SCAN_FAILED`; replacement storage cleanup still
  runs and records its existing compensation when necessary.
- Bearer API tokens reach only the six upstream-approved social write aliases:
  star PUT/DELETE and rating PUT under `/api/v1` and `/api/web`. Star/rating
  GET, subscriptions, ClawHub star aliases, admin, and other session-only
  routes remain unavailable to bearer-only callers.
- Private confirm-publish commits lifecycle state before reconciling search and
  durable owner/subscriber notifications. Replay uses the original durable
  publisher and `published_at`, is concurrency-safe, and does not duplicate
  audit or notifications.
- Durable notification rows are authoritative. In-process SSE fanout is
  best-effort and at-most-once; failure is logged after the durable commit and
  does not turn a successful confirm into an error.
- Aliyun-generated stop commands use the root `runtime.sh`, preserve
  `--aliyun`, and POSIX-quote dynamic URL/home values. Default GitHub commands
  retain `scripts/runtime.sh` and omit `--aliyun`.
- The upstream Java-only Bash launcher change is a no-op for the current
  POSIX-compatible Python launcher.
