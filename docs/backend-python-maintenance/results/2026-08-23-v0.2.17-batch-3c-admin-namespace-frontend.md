# Upstream v0.2.17 Batch 3C: Admin Namespace Frontend

Date: 2026-08-23

## Outcome

The Python-owned administrator namespace router now has a focused,
deterministic OpenAPI export and generated TypeScript contract. The React app
adds a separate SUPER_ADMIN page at `/admin/namespaces`; the existing
`/admin/namespace-analytics` page and its eligible-catalog semantics are
unchanged.

## Contract And Query Integration

- The exporter includes the exact 13-method route inventory from
  `app.api.admin_namespaces` and therefore derives request and response models
  from the running Pydantic contracts rather than duplicated declarations.
- `generate-api:admin-namespaces` regenerates the focused JSON and TypeScript
  declaration. `check-api:admin-namespaces` uses `openapi-typescript --check`
  and is wired into the frontend PR job.
- Admin namespace query hooks use the generated schema types and TanStack
  Query for list filters, detail, members, and member candidates.
- All mutations use the shared base-path-aware request boundary and browser
  CSRF header helper. The batch endpoint is typed but intentionally has no
  first-page control.
- Successful writes invalidate the admin list/detail/member/candidate scopes
  plus the existing `namespaces/my`, detail, and member caches.

## Page Behavior

- Unfiltered lifecycle cards show total, ACTIVE, FROZEN, and ARCHIVED counts.
- List filters cover keyword, status, type, and pagination. Selection opens a
  responsive detail surface with management counts, the actor's real
  membership role, and the explicit platform override.
- GLOBAL is visibly read-only. TEAM buttons are rendered exclusively from the
  backend capability flags, including ACTIVE, FROZEN, and ARCHIVED behavior.
- Member management supports candidate search, add, role changes, removal,
  and transfer to an existing non-owner member.
- Removal, ownership transfer, freeze, unfreeze, archive, and restore use
  focus-safe confirmation dialogs. Freeze and archive accept an optional
  reason with a visible 512-character boundary.
- Confirmation state captures the namespace slug and display name when the
  dialog opens. A list refetch or reorder cannot redirect a pending member,
  role, ownership, or lifecycle action to a different namespace.
- Members use backend pagination at 20 rows per page with visible total/page
  context and accessible previous/next controls. Paging resets when the
  selected namespace changes, so members beyond the first 100 remain
  reachable for role, removal, and ownership actions.
- Lifecycle writes also invalidate the existing Namespace Analytics query
  scope. Status, namespace type, and member roles are translated in every
  badge, filter, option, and detail field.
- Add/update-member request contracts expose only `ADMIN | MEMBER` in
  Pydantic/OpenAPI/generated TypeScript; `OWNER` remains possible only in read
  responses and the dedicated ownership-transfer workflow.
- Loading, empty, request error/retry, mutation success, and mutation failure
  states are visible. Long slugs, names, emails, and descriptions wrap, and
  the mobile layout uses bounded min-width containers without table overflow.
- The user menu item is SUPER_ADMIN-only. Lazy routing and the existing
  runtime base-path handling preserve both `/admin/namespaces` and
  `/skillhub/admin/namespaces` behavior.
- English, Simplified Chinese, and Traditional Chinese resources contain the
  same complete key set.

## TDD Evidence

The first backend contract run failed because the exporter did not exist. The
first frontend feature run failed because the generated-type hooks were
absent. Route, menu, locale, and page tests then failed for the missing page
and translations before those surfaces were added. Focused tests cover filter
serialization, CSRF mutation requests, cache invalidation, route/menu role
visibility, lifecycle capability matrices, and confirmation/reason behavior.

Review follow-up tests first reproduced the stale-target bug by reordering the
namespace list while a confirmation remained open; the mutation incorrectly
used the new first slug. Separate RED tests exposed first-page member
truncation, immediate unconfirmed role writes, missing analytics invalidation,
raw enum labels, and the generated `OWNER` request option. Each now has a
focused regression test, including second-page ownership and namespace-change
page reset.
