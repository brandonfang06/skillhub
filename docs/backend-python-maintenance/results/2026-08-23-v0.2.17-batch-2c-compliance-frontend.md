# Upstream v0.2.17 Batch 2C: Compliance Frontend

Date: 2026-08-23

## Outcome

The Python-only fork now consumes the additive compliance projections delivered by
Batch 2B and presents them as **publisher declarations**, not as verified
certification or runtime evidence.

This batch added a schema-only Python OpenAPI contract and exporter. It did not change
runtime backend behavior, database migrations, admin namespace features, product
routing, or deployment configuration.

## Official upstream contract evidence

The contract source was the generated artifact in the official local tag:

```powershell
git show v0.2.17:web/src/api/generated/schema.d.ts
git diff v0.2.16..v0.2.17 -- web/src/api/generated/schema.d.ts
```

The local Python contract covers the same compliance concepts introduced by v0.2.17:

- `ComplianceEvidenceResponse`
- `ComplianceMappingResponse`
- `ComplianceSnapshotResponse`
- the additive `complianceSnapshot` projection composed into skill summary, version,
  and version-detail frontend types

The broad upstream diff also contains admin namespace additions. They were deliberately
excluded. The legacy core `schema.d.ts` has no compliance delta.

## Reproducible generated-type sync method

The broad `web` `generate-api` command still points at the removed Java-era
`/v3/api-docs` contract and is not used. The focused source of truth is now:

- Pydantic models in `server-python/app/skills/compliance_contract.py`
- deterministic exporter `server-python/scripts/export_compliance_openapi.py`
- generated OpenAPI `web/src/api/generated/compliance-openapi.json`
- generated TypeScript `web/src/api/generated/compliance-schema.d.ts`

Regenerate both artifacts from the Python contract:

```powershell
cd web
corepack pnpm@10.33.0 run generate-api:compliance
```

Freshness is enforced by `server-python/tests/test_compliance_openapi.py`, which
compares the checked-in JSON to a fresh deterministic render. TypeScript determinism
was verified by running the generation command twice and comparing both file hashes:

```text
compliance-openapi.json  SHA-256 8FF7E73248EF1359CD65CBF67D01560A5E57A7250225157D515AFD5739108819
compliance-schema.d.ts   SHA-256 3245BF0EC88D260C924AA222DD477DB9939FD76675978A647AC2D62C29FFEA31
second generation: both hashes unchanged
```

`web/src/api/types.ts` composes the generated core response types with the focused
generated `ComplianceProjection`; it does not declare compliance fields or shapes by
hand.

The runtime projection boundary also uses these same Pydantic models. Tolerant parsing
still skips malformed items and returns `None` for absent or malformed snapshots, then
the normalized snapshot is validated through `ComplianceSnapshotResponse` before its
alias-preserving JSON dictionary is inserted into list, detail, search, and review
responses. The former duplicate `TypedDict` contract was removed. `extra="forbid"` and
alias tests ensure accidental fields cannot silently diverge from the exported schema.

Durable TypeScript freshness checking is available locally and is wired into the web
job in `.github/workflows/pr-tests.yml`:

```powershell
cd web
corepack pnpm@10.33.0 run check-api:compliance
# openapi-typescript --check; exit 0 only when compliance-schema.d.ts is current
```

## UI behavior

- Skill cards show at most two compact declaration badges and a `+N` overflow count.
  Empty snapshots render no badges. Badge accessible names explicitly say
  "publisher declaration" in the active locale.
- Each skill-version row can expand a declaration panel containing mapping count,
  schema version, full snapshot digest, mappings, evidence paths or URLs, and hashes.
- Detail copy explicitly says the values are supplied by the publisher and are not
  verified SkillHub certification or runtime evidence.
- Review detail chooses the previous `PUBLISHED` version deterministically: newest
  valid `publishedAt`, then highest ID, then version text. It does not compare against
  another draft or pending version when no published base exists.
- Review changes are keyed by normalized `standard`, `version`, and `controlId` and
  reported as added, removed, or modified. Evidence ordering alone does not create a
  false modification.
- English, Simplified Chinese, and Traditional Chinese resources contain the same
  compliance and review-diff keys.
- Disclosure controls use native buttons or `details`/`summary`; the skill-detail
  button exposes `aria-expanded` and a stable `aria-controls` target. Only the empty
  target remains mounted while collapsed; the mapping/evidence tree is created on
  expansion. A 50 mappings × 10 evidence test verifies the collapsed DOM contains zero
  evidence rows and the expanded DOM contains 500.
- Compliance containers use `min-w-0`, `overflow-hidden`, `break-words`, and
  `break-all` at long URL, path, digest, and hash boundaries to prevent horizontal
  overflow. The production subpath browser test expands a declaration containing a
  long URL and SHA-256 value and asserts no document-level overflow at both 1440 px and
  390 px viewports.
- No internal route or absolute application URL was added. Existing relative Vite
  assets and runtime base-path behavior therefore remain valid at both `/` and
  `/skillhub`.
